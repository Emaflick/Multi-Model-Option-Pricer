# qpricer — project memory for Claude Code

## Mission
Generate, end to end, a compact but rigorous **multi-model option pricer** (BSM, Heston, SABR) for vanilla and
exotic options (barrier, Asian, mono-asset autocallable), with **SPX implied-vol surface calibration**
(least squares) and a **Monte Carlo vs closed-form/Fourier benchmark**. Outputs: tested code, a results report,
and interview study material.

## Context
- Owner: MSc Mathematical Engineering (QF) student, basic Python. The code is generated by Claude Code; the owner
  supervises theory and validation and must defend every result in a Financial Engineering interview
  (front-office derivatives pricing team).
- **Deadline-driven:** correctness and explainability beat breadth. Prefer the simplest method that passes the gates.
- Mode is **AUTO**: implement directly. But every core module must ship with its derivation note and interview
  cheat-sheet (see Deliverables) — code the owner cannot explain is a liability.

## Architecture (engine-agnostic, keep it small)
```
src/qpricer/
  market.py        MarketData(F, DF, T) per expiry; implied F/DF from put-call parity
  models/          bsm.py, heston.py, sabr.py       (params, char. functions, implied-vol formulas)
  products.py      payoff definitions only (vanilla, barrier, asian, autocallable)
  engines/         analytic.py, fourier.py (COS + Lewis), mc.py (paths, schemes, variance reduction)
  calibration.py   losses, least_squares wrappers, multi-start, diagnostics
  data.py          SPX chain loading/cleaning
  iv.py            implied-vol inversion
scripts/           fetch_spx.py, run_calibration.py, run_benchmarks.py, make_figures.py
tests/             pytest; tests/golden/ holds frozen oracle values
docs/derivations/  one math note per topic
docs/interview/    one cheat-sheet per topic
report/            REPORT.md + figures/
```
Target size: core `src/` ≲ 1500 lines. No frameworks, no classes where a function suffices.

## Conventions
- Pricing kernels are **forward-based**: inputs `F, DF, T`; never raw `r`/`q` inside kernels.
- Time ACT/365F, continuously compounded rates, vols annualised decimals.
- `float64`, NumPy-vectorised (no Python loops over paths/strikes). Only numpy, scipy, pandas, matplotlib, yfinance.
- Randomness only via an explicit `np.random.Generator(seed)`. Every MC result returns `(price, stderr, n_paths, seed)`.
- Type hints; docstrings give the formula, the equation number in `docs/derivations/<topic>.md`, and the reference.
- `ruff check` + `ruff format`, line length 100.

## Verification gates (non-negotiable)
A phase is done only when its gates in `docs/ROADMAP.md` pass. Generic principles:
1. Two independent methods agree within stated tolerance (closed form vs Fourier vs MC).
2. Limiting cases reproduce a simpler model.
3. No-arbitrage identities hold (put-call parity, in+out = vanilla, monotonic/convex in K).
4. MC comparisons are stated in standard-error units (pass = within 3 SE); MC error decays ~ N^-1/2.

## Hard rules
- **Never modify existing files in `tests/golden/`** (a hook enforces it). New golden files may be created only by
  the `validator` agent, from a method independent of the implementation, with the source stated in the file.
- Never loosen a tolerance, never add `skip`/`xfail`, never special-case a test input to make it pass.
- On failure: suspect the math (convention, sign, measure) first, then code, last the test. Max 3 fix attempts per
  gate; then stop and write the failure + diagnosis to `docs/OPEN_ISSUES.md`.
- **No fabricated data or numbers.** Every number in the report comes from a script in this repo, re-runnable.
  If SPX data cannot be fetched, stop and say so; never silently substitute synthetic data. Synthetic data is
  always labelled `synthetic`.
- Every non-obvious modelling choice → entry in `docs/DECISIONS.md`.
- Commit at the end of each phase: `git commit -m "phase N: <summary>"`. Never push.

## Commands
- Fast tests: `pytest -m "not slow" -q` · All tests: `pytest -q`
- Lint: `ruff check src tests scripts && ruff format src tests scripts`

## Pipeline
`/build-all` runs every phase. Single steps: `/phase <n>`, `/research <topic>`, `/validate <module>`,
`/report`, `/cheatsheet <topic>`, `/grill <topic>`. Agents live in `.claude/agents/`.
