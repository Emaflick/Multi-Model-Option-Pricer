## Independent methods (no qpricer numerics in any reference)

- **B76:** my own Black-76.
- **GP:** Heston by Gil-Pelaez (P1/P2), little-trap CF, `scipy.integrate.quad` on [0, ∞).
  - It differs from the implementation's COS by 7.36e-9 (cal, F = 7678) and 1.9e-10 (FO).
  - It agrees with the implementation's Lewis to 1e-12.
- **VRCF:** population VR factors under exact BSM.
  - CV with X = F_T: closed form from lognormal partial moments.
  - Antithetic: Cov(g(Z), g(−Z)) by 400-node Gauss–Hermite.
- **CVB:** the leading O(1/N) bias of the regression CV, −E[x²e]/(N Var X), by quadrature.
- **OQE:** my own Andersen QE-M (ψ_c = 1.5, γ₁ = γ₂ = ½, martingale correction).
  - The exponential branch uses an independent uniform (the implementation uses Φ(Z_v)).
  - So the code is independent and the law is the same.
- **EST:** my own plain, pair-mean antithetic, OLS-β CV and RQMC estimators.
  - RQMC uses scipy scrambled Sobol' with **bits = 53**, so no jitter is needed (a different fix from D-042).
- **REGEN:** an independent full `run_benchmarks.py` run into a scratch directory, compared file by file.

**Sobol' rates.**
- **BSM.** −1.0 to −1.1 is right for this estimator. In 1-D a scrambled net is a stratified sample. For a Lipschitz
  payoff that would give RMSE ∝ N^-1.5, but the inverse-CDF map makes the payoff unbounded or steep in the edge cells
  (u → 1 for the call). Those cells contribute variance ∝ N^-2, hence rate ≈ −1. My bits-53 RQMC shows the same rate.
- **Heston.** −0.51 to −0.63 (64–68 dimensions, time-ordered, no Brownian bridge) is plausible: a constant-factor gain
  only, as D-043 says.

## Findings

No blockers. Both ROADMAP gates pass, and my independent references, estimators and fresh seeds reproduce them.

1. **Minor (documentation): the RQMC SE is calibrated in mean square, not in its tails.** The per-scrambling RQMC
   error is right-skewed (BSM ATM: skew +1.67, excess kurtosis 4.4–4.8; put: skew +1.1–1.3). It is the same for the
   jittered bits-30 nets and my bits-53 nets, so the cause is LMS + digital-shift scrambling of a payoff that is
   unbounded in u, not the jitter.
   - **Effect on the t-statistic.** The 16-scramble t-statistic has P(|t| > 3) = 1.8–3.2 %, against 0.9 % for t₁₅
     and 0.27 % assumed by the 3SE convention.
   - **In the on-disk run.** BSM Sobol' has mean z² of 1.43 / 1.54 (t₁₅: 1.15) and six runs with |z| > 3.5. All are
     negative, and one is z = −6.17 (put, N = 2^17, rep 7). The pooled BSM ATM Sobol' z = −2.01 is the same effect.
   - **What the implementation reports.** The D-040 `se_ratio` (1.01 / 1.04) is a mean-square check, so it cannot see
     this. Yet D-043 says "the 16-scramble RQMC SE [is] calibrated".
   - **Fix (wording only).** Qualify that sentence in D-043 and in the report: "calibrated in mean square; the
     t-statistic is heavy-tailed (skewed scrambles), so no single-run 3SE claim on Sobol'". This is consistent with
     D-042, which already makes no single-run claim.
   - Documented by `test_rqmc_scramble_errors_skewed_t_tails_heavy` (slow, passes).
2. **Minor (documentation): the QE-M bias is reported selectively.**
   - **Omission.** D-043 leaves out the largest fine-grid bias: put at T/17, −0.66 ± 0.15 (−4.35 SE). My run gives
     −0.93 ± 0.15; combined −0.80 ± 0.11, −3.2 vol bp.
   - **Non-monotone in Δt.** The put bias is +0.37 → −0.80 → −0.40 → −0.28 as Δt halves. "Halving differences ≤ 1.3 SE"
     is true, but it hides the shape.
   - **Not reproduced.** The T/9 put "+0.56 (3.7 SE)" is not significant in my run (+0.17, 1.1 SE; combined
     +0.37 ± 0.11).
   - **Fix.** Report the full ladder, as in the table above.
3. **Minor (gate weight): 6 of the 52 gate lines cannot fail.** The SE fit regresses s/√N on N, so its slope is −0.5
   by construction for any code that computes a sample SD. "52/52" therefore overstates the evidence.
   - The plain-MC slope gate in general has little power against SE bugs. For example, an antithetic SE computed from N
     correlated payoffs would still have slope −0.5.
   - The power comes from the SE-honesty ratio (reported, not gated) and from my fresh-seed honesty tests.
   - **Fix.** Present the error-metric fits as the gate, and the SE fits as a sanity line.
4. **Minor (process): the pre-declaration cannot be verified from git.** D-039 and D-040 sit in the same uncommitted
   diff as the D-043 results.
   - **Mitigation.** The procedure has nothing left to tune: all 11 points, all 6 (case, strike) pairs, both fits, a
     fixed seed formula. It is robust to seeds: 0/104 of my fresh-seed fits fall outside the band, with slope sd
     0.014–0.032 against a half-width of 0.1. It is bit-reproducible: G2′.
   - **Assessment.** I see no sign of tuning. The only admitted post-hoc change, the jitter, is legitimate (finding 7).
5. **Minor (numeric slips in DECISIONS).**
   - D-042 says the first full run "drew ≈ 1.2e10 coordinates". My count for one full run is 5.3e9 (4.46e9 replication
     + 0.84e9 timing pass), i.e. about 4.9 expected zero hits. The conclusion (a hit was to be expected) is unaffected.
   - D-043 gives "VR_err … ±35 %". For a ratio of two 15-dof variances the log-sd is √(4/15) ≈ 0.52, i.e. roughly
     ±50–70 %. That range covers the observed VR_err 0.48 vs VR_se 1.11 (heston_cal antithetic put).
6. **Minor (timing).** My rerun on the same machine reproduces the Heston efficiencies within +0.6 % to +9 %, matching
   D-043's "±10 %". The BSM efficiencies moved by 9–22 % (Sobol' −22 %), because the BSM times are 11–29 ms. D-043
   should limit the ±10 % statement to Heston, and call the BSM efficiencies indicative.
7. **No finding: the D-042 jitter is sound.**
   - u ← u + U·2^-30 keeps every point inside its own 2^-30 cell, so the net property holds at every resolution
     ≥ 2^-30.
   - The digital shift makes each coordinate uniform on the 2^30-point grid, so the jittered coordinate is exactly
     U(0, 1). It is unbiased, which also removes the O(2^-30) left-endpoint bias of the raw grid.
   - It cannot bias anything at N ≤ 2^16 points per scramble.
   - A residual boundary value has probability ≈ 2^-53 (low end) and ≈ 2^-54 (high end) per coordinate, and it still
     raises.
   - My bits-53 alternative gives statistically identical results.
8. **Minor (regeneration-gate design).** The manifest is written by the script being audited, and `written_by` is a
   string literal. The sha256 match therefore proves integrity since the run, not provenance. Two further points:
   - The real evidence is reproducibility, which my independent full rerun supplies: G2′, bit-identical except for
     timing.
   - The stray check covers only `benchmark_*.png`, not CSVs. There are no stray files today.
   - **Fix.** State in the report that provenance rests on deterministic regeneration. Optionally, extend the stray
     check to `benchmark_*`.
9. **Minor (edge cases, not reached by the benchmark).**
   - `vanilla_mc(method="cv")` raises at σ = 0 (zero control variance). The other methods return intrinsic value with
     SE 0.
   - All-zero payoffs (BSM K = 3F, N = 4096) return price 0 and SE 0, with a 0/0 `RuntimeWarning` from the VR ratio in
     `control_variate`.
   - Everything else I probed behaves correctly: T = 1e-6 BSM and T = 1e-4 Heston (n_steps = 1), ρ = −0.99, ρ = +0.9
     with ξ = 1.65, ξ = 1e-6, Sobol' with 1 point per scramble, and the invalid-N errors.
10. **Minor (size, carried forward).** `src/` is 2644 lines (vr.py +162), against the ≲ 1500 target. Author's decision,
    as in Phases 4 and 5.

**Observation (not a finding).** My Heston noise-slope means (−0.479 to −0.489, 6 trials each) sit slightly above
−0.5, while the implementation's four are below it (−0.517 to −0.554). My cal and FO trials share seeds, so they are
correlated. The deviation is about 1.8 sd of a 6-trial mean: not significant.
